# Persistent Ary conversation and Ambient Mode

September 9, 2026. Implementation extends the existing voice and conversation path. Physical microphone/acoustic and installed-desktop background acceptance remain separate from automated and synthetic-provider verification.

## Audit and decision

Already present and retained: `SpeechToTextProvider`, `TextToSpeechProvider`, `VoiceService`, OpenAI transcription deltas, Responses text streaming, sentence-level `SpeechQueue`, mute/cancel, `AryBrainService`, conversation identity, extraction jobs, evidence, hybrid retrieval, action/permission/approval/outcome infrastructure, durable MissionEngine, Nexus events, real visual presence, Ambient/Systems shell, and the Electron launcher. Manual microphone/transcript-review mode remains available. No new database, audio store, brain, reasoning framework, model selection, credential, or dependency.

## Delivered behavior

- **Start conversation** explicitly acquires a microphone. There is no capture on load, automatic restart after reload, or wake-word activation. The existing saved conversation resumes; microphone consent does not persist across reload.
- A fixed same-origin AudioWorklet transfers mono PCM to an Ary-owned capture adapter. It writes silence to the audio output, never plays back captured input, and uses no network or storage. Sample processing is independent of animation frames.
- Local VAD requires 200 ms of sustained energy. A bounded 360 ms pre-roll preserves onset; 650 ms of silence ends a turn. These are signal heuristics, not guarantees that a thought is complete. Continuous turns exceeding 20 seconds stop with an explanation rather than submit a truncated command. The existing manual recorder supports longer, reviewed input.
- Speech onset immediately stops queued/playing TTS and invokes the existing response cancellation path. Stale transcription requests are aborted and their late results ignored. New final input waits for the previous Brain request to settle before using the same conversation ID. No automatic HTTP retry or replay of an uncertain user turn.
- Completed turns go to the existing `voice/transcribe` endpoint, then `Dashboard.send` with `modality: voice`, then the same `/api/chat` and Brain services used by text. Only final transcripts are sent to Brain. Provider deltas are ephemeral previews.
- Brain text streams while it is generated; existing speech synthesis begins at sentence boundaries with one-segment prefetch. Synthesis currently buffers each returned audio segment before playback. This is a persistent turn-based conversation, **not continuous cloud audio ingress or sub-second speech-to-speech delivery**.
- Existing tool requests, mission actions, approvals, memory extraction, audit and outcomes remain authoritative. The narrow existing orchestration conversation router now recognizes “Create a mission to …” and requests the already registered `mission.create`. It creates a durable **DRAFT** only; planning and activation remain explicit. Replays use the source-message execution key. Chat links to the existing Mission Control view.
- Approval dialogs pause segmentation and discard unsubmitted audio. A generic spoken “yes” grants nothing. Existing deliberate, exact-snapshot orchestration review commands retain their current permission checks; no new voice approval endpoint exists. Inline task approvals remain owner clicks on the current TaskProposal.
- There is one continuous microphone owner per browser origin through Web Locks. A second window fails immediately instead of silently starting later. Existing command-palette opening and conversation switching stop the Dashboard session.

## Background, stop and privacy

Background listening is an explicit per-session UI choice, initially off. With it off, hiding the document stops capture and speech. With it on, module navigation and document hiding retain the current session. Browser throttling or OS suspension can still interrupt web tabs. The installed Electron launcher disables background throttling, exposes **Stop voice session** in its menu, and sends a fixed suspension event on macOS lock/sleep. Quit, reload, sign-out, offline, device removal, emergency stop, and explicit End/Stop release capture. Sessions end after five minutes without detected speech or a 30-minute total limit; they do not restart automatically.

Restart the installed Ary app to load the desktop lifecycle changes: its existing bootstrap loads `desktop/main.cjs` from this repository. Nothing was repackaged or replaced in the installed application.

The session banner and desktop title identify microphone activity. **Mute Ary** affects output only; **End conversation**, **Stop voice**, the global stop control, and the desktop menu stop capture. Raw audio stays in bounded memory, is sent only for an ended speech turn, and is not persisted by Ary. Provider retention policies still apply. Debug events carry state/timing, not PCM or transcript content. Canonical messages/evidence and existing provider action metrics retain their original storage rules.

## Visual integration

Ambient → Chat becomes a calm conversational surface using the existing event-driven presence, materials and controls. It shows the latest real user/assistant exchange, ephemeral transcription, session status, output mute, background choice and approval access. **Conversation & evidence** returns to Systems Mode without changing conversation identity. The same presence reflects listening, transcription, Brain work, speaking, tool/mission work and approvals. There is no invented idle activity. PCM energy lives in a ref rather than causing component renders on every audio frame. Existing reduced-motion/static presence remains authoritative.

## Manual installed-app acceptance

1. Restart Ary, select **Ambient**, and choose **Start conversation**. Confirm macOS microphone permission and the visible microphone indicator.
2. Say a short durable fact. Pause and confirm it saves. Ask a paraphrase, then use Systems to inspect retrieved memory/evidence.
3. Interrupt while Ary speaks. Confirm immediate output stop, a correct new transcript and no later replay of interrupted speech. Test both headphones and speakers; record false positives/missed words.
4. Say “Create a high priority task to verify the tracking fix for Wag Trails tomorrow.” Review and approve the existing task proposal; ask “What task did you just create?” Check its real ID and Action History.
5. Say “Create a mission to validate the Wag Trails release.” Open its draft in Mission Control. Confirm it has not started execution.
6. Hide the app with background listening off: capture stops. Start again with it on: speak while hidden. Then use the desktop **Stop voice session** menu. Lock/sleep and verify capture stops and does not restart on unlock.
7. Test microphone removal, offline, End conversation, STOP CONTROL, a second browser window, and reduced-motion mode.

Physical mic accuracy, speaker echo/false barge-in, native minimized/locked operation and real end-to-end first-audible latency **have not been accepted by this automated run**. Do not promote this to full live voice acceptance based on synthetic tests. Next refinement within voice is acoustic testing, then Silero/true streaming transcription if measurements justify them. No unrelated milestone starts automatically.
